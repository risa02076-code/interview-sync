# 통합 검증 스크립트

`lib/*.test.ts`(Vitest)는 순수 로직만 검증한다. 이 폴더의 스크립트는 그와 달리 여러
API 라우트와 실제 Supabase를 오가는 **전체 흐름**을 검증한다 — 로컬 개발 서버와 실제
DB가 있어야 하므로 CI에서 자동으로 돌지 않고, 수동으로 실행하는 통합 검증용이다.

## 실행 전 필요조건

- `npm run dev`로 로컬 서버가 `http://localhost:3000`에서 실행 중이어야 함
- `.env.local`에 실제 Supabase 프로젝트 키가 있어야 함
- 스크립트 안의 `A`, `B` 상수는 시드 데이터의 실제 면접관 id(정민지, 신동혁)를 가리킴 —
  다른 DB에서 실행하려면 이 id를 실제 존재하는 면접관으로 바꿔야 한다

## 실행

```bash
node scripts/verify-reschedule-flow.js
node scripts/verify-wide-availability-flow.js
```

## 무엇을 검증하는지

- **verify-reschedule-flow.js**: 확정된 일정을 후보자가 변경 요청할 때, 라이브 데이터상
  이미 겹치는 시간이 있어도 조용히 확정하지 않고 면접관 전원에게 반드시 재확인을 받은
  뒤에만 확정되는지 검증한다.
- **verify-wide-availability-flow.js**: 후보자가 추천받은 시간을 전부 거절하면 같은
  응답 링크가 "다음 주 가능 시간 체크" 단계로 전환되고, 체크한 시간이 면접관 전원에게
  정확히 재확인 요청되는지, 그리고 그래도 안 된다며 자유 입력(가능 시점/사유)을 보내면
  리크루터 에스컬레이션으로 이어지고 대시보드에 노출되는지 검증한다.

각 스크립트는 `__검증__`류 이름의 테스트용 면접 케이스를 만들어 실행하고, 끝나면
스스로 정리(삭제)한다. 실행 중 실패하면(assert 실패) 어떤 조건이 깨졌는지 콘솔에 표시된다.

## 주의

실제 운영 DB(진짜 후보자 데이터가 있는 환경)에서는 절대 실행하지 말 것 — 면접관
`busy_slots`를 직접 덮어쓰고 이메일 주소를 임시로 바꾸는 등, 테스트를 위해 실제 데이터를
변형한다.
