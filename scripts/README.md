# 통합 검증 스크립트 · 데이터 백필

`lib/*.test.ts`(Vitest)는 순수 로직만 검증한다. 이 폴더의 스크립트는 그와 달리 여러
API 라우트와 실제 Supabase를 오가는 **전체 흐름**을 검증한다 — 로컬 개발 서버와 실제
DB가 있어야 하므로 CI에서 자동으로 돌지 않고, 수동으로 실행하는 통합 검증용이다.

`backfill-busy-slots.ts`만 성격이 다르다. 검증이 아니라 **기존 데이터를 고치는 1회성
작업**이고, 로컬 dev 서버 없이 Supabase에 직접 붙는다(아래 "데이터 백필" 참고).

## 실행 전 필요조건

- `npm run dev`로 로컬 서버가 `http://localhost:3000`에서 실행 중이어야 함
- `.env.local`에 실제 Supabase 프로젝트 키가 있어야 함
- 스크립트 안의 `A`, `B` 상수는 시드 데이터의 실제 면접관 id(정민지, 신동혁)를 가리킴 —
  다른 DB에서 실행하려면 이 id를 실제 존재하는 면접관으로 바꿔야 한다

## 실행

```bash
node scripts/verify-reschedule-flow.js
node scripts/verify-wide-availability-flow.js
node scripts/verify-priority-confirm-resend.js

# 아래는 로컬 dev 서버가 필요 없다(Supabase에 직접 붙는다)
npm run verify:confirm-transaction
```

## 무엇을 검증하는지

- **verify-reschedule-flow.js**: 확정된 일정을 후보자가 변경 요청할 때, 라이브 데이터상
  이미 겹치는 시간이 있어도 조용히 확정하지 않고 면접관 전원에게 반드시 재확인을 받은
  뒤에만 확정되는지 검증한다.
- **verify-wide-availability-flow.js**: 후보자가 추천받은 시간을 전부 거절하면 같은
  응답 링크가 "다음 주 가능 시간 체크" 단계로 전환되고, 체크한 시간이 면접관 전원에게
  정확히 재확인 요청되는지, 그리고 그래도 안 된다며 자유 입력(가능 시점/사유)을 보내면
  리크루터 에스컬레이션으로 이어지고 대시보드에 노출되는지 검증한다.
- **verify-priority-confirm-resend.js**: 발송 실패로 방치된 예전 요청(pending)이 있어도,
  "재발송"으로 만든 최신 요청에 전원이 답하면 자동 확정이 정상적으로 되는지 검증한다
  (면접관별 최신 요청 기준 판단 로직의 회귀 테스트).

- **verify-confirm-transaction.ts**: 확정을 하나로 묶는 DB 함수(`confirm_interview`)가
  실제로 약속대로 동작하는지 진짜 DB에 대고 확인한다. 이 함수는 plpgsql이라 tsc도
  vitest도 닿지 않아서, 단위 테스트는 "앱이 rpc를 올바른 인자로 한 번만 부르는지"까지만
  볼 수 있다. 그 마지막 한 칸을 메우는 검증이다 — ① 모든 쓰기 직후 강제 중단시켜도
  아무것도 안 남는지(원자성), ② 겹치는 확정이 `PT409`로 거부되고 그때도 아무것도 안
  쓰이는지, ③ `force`면 겹쳐도 진행되는지(수동 확정 동작 보존), ④ 두 확정을 동시에
  불렀을 때 정확히 하나만 성공하는지.

  **`supabase/migration_confirm_transaction.sql`을 Supabase SQL Editor에서 먼저 실행해야
  한다.** 함수가 없으면 데이터를 건드리기 전에 멈추고 무엇을 실행해야 하는지 알려준다
  (그러지 않으면 "함수가 없어서 실패한 것"을 "의도한 실패"로 잘못 세게 된다).

각 스크립트는 `__검증__`류 이름의 테스트용 면접 케이스를 만들어 실행하고, 끝나면
스스로 정리(삭제)한다. 실행 중 실패하면(assert 실패) 어떤 조건이 깨졌는지 콘솔에 표시된다.

## 데이터 백필 — backfill-busy-slots.ts

소요시간(`INTERVIEW_DURATION_MINUTES`)을 도입하기 전에 확정된 면접들은 `busy_slots`에
시작 슬롯 하나만 들어 있다. 10:00에 확정된 1시간 면접의 10:30이 비어 보이므로 같은
면접관·회의실에 10:30 면접이 또 잡힐 수 있다. 이 스크립트가 그 구멍을 소급해서 메운다.

```bash
npm run backfill:busy-slots            # 미리보기 — 무엇을 채울지 출력만 한다
npm run backfill:busy-slots -- --apply # 실제 반영
```

- **더하기만 한다.** 확정이 풀린 뒤에 남은 옛 슬롯을 지우지는 않는다 — `busy_slots`에는
  면접관 본인의 개인 일정도 섞여 있어 데이터만으로 구분할 수 없고, 잘못 지우면 없는
  시간에 면접이 잡힌다.
- 여러 번 실행해도 결과가 같다(멱등). 중간에 한 행이 실패해도 나머지는 계속 진행하고,
  다시 실행하면 남은 것만 채워진다.
- 반영한 뒤 `--apply` 없이 한 번 더 실행해서 "채울 슬롯이 없다"가 나오는지 확인할 것.
- 무엇을 채울지 계산하는 로직은 `lib/backfillBusySlots.ts`(순수 함수)에 있고 Vitest로
  검증된다. 이 스크립트는 그 결과를 출력하거나 DB에 쓰기만 한다.

## 주의

실제 운영 DB(진짜 후보자 데이터가 있는 환경)에서는 절대 실행하지 말 것 — 면접관
`busy_slots`를 직접 덮어쓰고 이메일 주소를 임시로 바꾸는 등, 테스트를 위해 실제 데이터를
변형한다.
